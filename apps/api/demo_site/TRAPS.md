# Agent traps in `demo_site/v0`

Zephyr Compute is a fake serverless-GPU SaaS site (marketing + docs) with deliberate
"agent traps". Each trap defeats some agent kinds (`text` = plain HTTP fetch, HTML->text,
no JS, sees hidden text; `dom` = headless Chromium reading visible innerText + numbered
interactive elements, cannot see CSS pseudo-element content; `vision` = headless Chromium
reading screenshots) and each has an obvious agent-friendly fix that the optimizer should
discover. Tasks in `tasks.json` reference traps by slug (`Task.trap`).

| Slug | Where it lives | What it does | Defeats | Expected fix |
|---|---|---|---|---|
| `js_nav` | every page: `<nav id="main-nav">` is empty in HTML; `assets/site.js` fills it ~800 ms after load. `changelog.html` is linked *only* from that nav. | Text agents see a header with no links and never discover the Changelog. | text (dom/vision only if they observe before the 800 ms timer fires) | Render the nav links as static HTML in every page's header (and/or add Changelog to the footer). |
| `canvas_prices` | `pricing.html`: GPU rate table is drawn onto `<canvas id="gpu-rates">` by `assets/pricing.js`. A `display:none` "GPU rate card / 2024 edition" `<aside class="legacy-rates">` next to it lists *different* (old) prices for the same GPUs. | Only vision can read the canvas. Text agents see the hidden legacy prices and confidently answer the wrong number; dom agents see no prices at all. | text (wrong answer), dom (no answer) | Replace the canvas with a real `<table>` of current prices; delete the hidden legacy block. |
| `hidden_tab` | `pricing.html` "Plans": tabs Starter / Team / Enterprise; Enterprise is active by default and only the active tab's panel exists in the DOM (`assets/pricing.js` renders the others on click). The Starter free monthly credit ($30) is only in the Starter panel. | Text agents never see the Starter content. dom/vision must click the Starter tab. | text; dom/vision if they don't click | Render all three plans side by side as static HTML (classic pricing cards). |
| `cookie_wall` | every page: `assets/site.js` appends a full-screen `#cookie-overlay` (fixed, z-index 9999) that intercepts every click until `#cookie-accept` ("Accept all") is pressed; consent is remembered in `localStorage`. | Browser agents that try to click through it get intercepted clicks / timeouts; vision agents see a dimmed page. Text agents are unaffected (no JS). | dom, vision | Remove the overlay, or make it a non-blocking bottom banner that does not cover the page. |
| `vague_links` | `docs/index.html` "Guides" grid: four `<h3>` topics, four `<p>` blurbs and four `<a>` links whose text is all "Learn more →" and whose hrefs are opaque article numbers (`articles/4410..4413`). CSS grid places them in columns so visually each column is a card, but DOM order is headings, then blurbs, then links. | Text agents (and dom agents reading innerText) cannot tell which "Learn more" goes with which topic. Vision sees the columns. | text, dom | Make the link text descriptive ("Web endpoints guide →") and/or wrap each card so heading + link are adjacent in the DOM; use descriptive slugs. |
| `unlabeled_form` | `waitlist.html`: email `<input>` with placeholder only (no `<label>`), a div-based custom dropdown (`.zc-select`, options only inserted into the DOM when opened) for "Primary use case" that must have a value, and a `<div role="button" onclick="ZC.submitWaitlist()">` instead of a `<button>`. Submission is a JS `fetch` POST to `api/event` with `{name:"waitlist_submit", payload:{email, use_case}}`. | Text agents cannot submit at all (no JS, no `<form>`). dom agents must find unlabeled fields, open the fake dropdown, pick an option and click a div. | text; dom/vision partially | Use a real `<form>` with `<label>`s, a native `<select name="use_case">`, a real `<button type="submit">`, and a form-encoded `action="api/waitlist_submit"`. |
| `accordion` | `docs/limits.html` "Sandboxes": four collapsed accordion items; `assets/limits.js` inserts the panel content (e.g. "Maximum sandbox timeout: 24 hours") into the DOM only when the header is clicked. The visible "Functions" table lists a *different* maximum timeout (12 hours) as a decoy. | Text agents see only the headers (or answer with the function timeout). dom/vision must click to expand. | text; dom/vision if they don't expand | Render the sandbox limits as a plain table like the functions table. |
| `css_email` | `contact.html`: the support address is rendered only by CSS: `.support-email::after { content: "help@zephyrcompute.io" }` on an empty `<span>`. | Pseudo-element content is not in the DOM/innerText, so text and dom agents see "reach the support team by email at" followed by nothing. Vision reads it from the screenshot. | text, dom | Put the address in the HTML as a `mailto:` link. |
| `expand_table` | `docs/python-versions.html`: the versions table initially shows only "Python 3.12 (Default)" and a row "and more… [Show all]". `assets/pyversions.js` replaces the rows with 3.9–3.13 on click. | Text agents answer 3.12 (wrong) or give up. dom/vision must click "Show all". | text; dom/vision if they don't click | Render the full table statically. |
| `fake_select` | `docs/regions.html`: a div-based custom dropdown (`#region-select`) whose options are populated by `assets/regions.js` on first open; region details appear only after a region is chosen. No region IDs exist in the HTML. | Text agents see "Select a region" and nothing else. dom/vision must open the dropdown (and can read the option labels, which include the IDs). | text; dom/vision if they don't interact | Render a static table of regions (ID, location, GPUs); if a picker is wanted, use a native `<select>` with options in the HTML. |
| `control` | `index.html` hero `<h1>` (tagline), `docs/quickstart.html` (`pip install zephyr-cli` in plain text), `newsletter.html` (plain `<form method="post" action="api/newsletter">` with a `<label>`ed email input and a real `<button type="submit">`). | Nothing; these should pass for every agent kind and give a baseline. | none | n/a |

Notes
- All facts are stated exactly once (plus the deliberate hidden decoy for GPU prices). Prices, plan
  credit, timeouts, Python versions, regions and the support email do not appear anywhere else.
- Everything is relative-linked and works offline; there are no external assets.
- `assets/site.js` forwards `?abtract_ep=<id>` from the page URL into `api/...` requests (query
  string + `X-Abtract-Episode` header on fetch) so the hosting server can attribute events.
